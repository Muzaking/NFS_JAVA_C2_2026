# Day 17 Security Hardening Evidence

## 1. Missing Token Returns 401
**Test:** Sent a `GET` request to a protected endpoint (`/api/v1/assets`) without an `Authorization` header.
**Result:** Spring Security filter chain intercepted the request and returned a `401 Unauthorized` status. 
**Evidence:** 
![401 Missing Token](../screenshots/401-unauthorized.png)

## 2. Wrong Role Returns 403
**Test:** Authenticated as a standard user (`testuser99@example.com` with `ROLE_USER`) and sent a `POST` request to an admin-only endpoint (`/api/v1/assets`).
**Result:** Authentication succeeded, but authorization failed. The server returned a `403 Forbidden` status because the user lacks the `ADMIN` authority.
**Evidence:** 
![403 Forbidden](../screenshots/403-forbidden.png)

## 3. Duplicate Record Returns 409
**Test:** Attempted to create a new record via `POST` using an `assetTag` that already exists in the MongoDB collection (`LAP-2026-001`).
**Result:** The `@Indexed(unique = true)` constraint triggered a database exception, which the global exception handler mapped to a `409 Conflict` status.
**Evidence:** 
![409 Conflict](../screenshots/409-conflict.png)

## 4. Invalid Input Returns 400
**Test:** Sent a `POST` request with missing mandatory fields (`category`, `location`, `serialNumber`).
**Result:** Spring Validation (`@Valid`) rejected the payload before it reached the service layer, returning a `400 Bad Request` containing an array of specific field errors.
**Evidence:** 
![400 Bad Request](../screenshots/400-bad-request.png)

## 5. Logs Do Not Show JWT Tokens or Passwords
**Verification:** Reviewed the console output generated by `RequestTimingFilter` and Spring Security.
**Result:** The application logs request URIs, HTTP methods, and execution durations (e.g., `GET /api/v1/assets took 44ms`). Headers, JWT payloads, and raw JSON bodies (which contain passwords during login) are strictly excluded from all logging mechanisms.

## 6. Environment Variables Are Not Committed
**Verification:** Checked the `.gitignore` file and repository history.
**Result:** Secret keys and database URIs are stored in `application-local.properties` (or `.env`), which is explicitly ignored by Git. Only the safe `application-local.properties.example` template is committed to the repository.
